# 画面の仕様

デザインは `design/screens/*.png`（元は Claude の Design キャンバス「改訂案」ページ）。実装は `web/src/pages/` にあり、モックで動きます。ここには、画像だけでは分からない動きと、決めたこと・決まっていないことを書きます。

## 共通

- **左のメニュー**：運用／設定（映像・伝送・録画）／管理（ネットワーク・ログ・機器情報）。未適用の変更がある設定画面には件数のバッジを出す。
- **ヘッダー**：機器名・役割・IP アドレス、状態（形と文字）、機器の時刻（`10:42:18 JST`）。時刻は機器の時計で、ブラウザの時計ではない。
- **警告の帯**：ヘッダーの下。▲ 警告（黄）、■ 接続エラー（赤）。自動では消えない。直せる画面があるときだけリンクを添える（いま開いている画面へのリンクは出さない）。
  - 送信機：余裕の警告（`delay_margin_low`）と入力の異常は「映像設定を開く」、接続エラーと損失の警告は「伝送設定を開く」。
  - 受信機：リンクなし（受信機の設定画面は未デザイン。映像の停止は送信機の画質で直す）。
- **状態の形**：● 正常 ▲ 警告 ■ エラー ○ 停止・待ち受け — 未取得。色だけで区別しない。
- **配色**：白基調、強調は黒（`web/src/styles/app.css` の変数）。文字 14px、角丸 4px、数値は等幅数字。
- **確認ダイアログ**：停止と取り消しは赤いボタン。開いたら安全な方のボタンにフォーカス、Esc で閉じ、閉じたら元の場所へフォーカスを戻す。

## 運用（送信機・受信機）

- 左：入力映像（送信機）／受信映像（受信機）のプレビュー、形式、「全画面」、音声（いまは「なし」）、信号経路。
- プレビュー：送信機は **送っている映像**（圧縮したあとの画質。入力より数秒遅れる）、受信機は **出力している映像**（少し遅れる）を、確認用に映す（既定では解像度とフレームレートは元のまま）。下に一行の説明を添える（送信機「受信機へ送っている映像を、圧縮したあとの画質で確認用に表示しています。入力より数秒遅れて映ります。」、受信機「受信機が出力している映像を、確認用に表示しています。出力より少し遅れて映ります。」）。
  - 映すのは伝送中（受信中）で映像があり、タブが前に出ている間だけ。それ以外は今までの表示（「入力映像」「受信映像なし」）で、停止中などは「プレビューは伝送中だけ表示します。」と添える。別の画面へ移る、タブを裏に回す、伝送が止まる、のどれでもプレビューを閉じて機器の負荷を減らす。
  - 準備中は「プレビューを準備しています」。表示できないときは「プレビューを表示できませんでした」と、伝送には影響がないこと（送信機「受信機へ送っている映像には影響ありません。」）、「もう一度試す」。ほかの画面で見ている人が多いとき（機器の上限、既定 3）は「ほかの画面でプレビューを見ているため、表示できません」と「ほかの画面を閉じてから、もう一度試してください。」。ブラウザが対応していないときは「このブラウザではプレビューを表示できません」「Google Chrome か Safari で開いてください。」（ボタンなし）。Firefox は、ネットから部品を取ってくるまで対応する方式を持たないので、オフラインでは映らない。Firefox には合わせない（2026-11-04 の判断）。
  - 映っていた接続が切れたときは、3 → 6 → 12 → 30 秒と間隔を延ばして自動でつなぎ直す（「少し待つと、自動でもう一度つなぎます。」）。
- 右：計測値 4 つと直近 5 分の推移、「回線の詳細」、停止・開始ボタン。
  - 送信機：画質（実際）＋目標、映像が止まるまでの余裕、回線の損失（再送で補っています）、送っているデータ量（1 秒あたり。送り直した分を含む）。詳細は回線の往復時間、回線の推定容量（回線が混んでいるときだけ測れる。空いているときは「— 余裕あり（混んだときだけ測ります）」）、送りきれずに捨てたデータ（直近 5 分）、遅延の設定。
  - 受信機：受け取っているデータ量、回線の損失、直近 5 分で映像が止まった回数（合計秒数）、映像の遅れ。詳細は回線の往復時間、送り直して届いた割合、届かなかったデータ（直近 5 分）、遅延の設定。
  - 映像の遅れは、実測できるまでは「映像の遅れ（目安）」として遅延の目標（標準なら 9.5 秒）を出し、「入力から表示まで。まだ実測していません」と添える。
  - 余裕が機器の基準（`Stats.delay_margin_warn_s`、標準の遅延では 3 秒）を下回ると ▲ を付ける（機器の警告 `delay_margin_low` と同じ基準）。損失は標準の遅延では再送で補うので、基準も警告も出さない。
  - 詳細の値が 0 でない警告（捨てたデータ、届かなかったデータ）は、色に加えて ▲ と「映像が乱れたおそれ」を付ける。
  - 取れない値は「—」と理由（未接続のため取得できません／未取得（前回 38 ms）／停止中）。
- 推移の線：縦の幅はデータに合わせるが、小さな揺れが大げさに見えないよう最小の幅を決めている（画質と送受信 1 Mbps、余裕 4 秒、損失 2%）。破線は意味のあるところだけ（画質の目標、余裕の警告の基準）。受信機の停止は縦線で示す。
- 信号経路：送信機は 入力 — 圧縮 — 送出 — 回線 — 受信機、受信機は 送信機 — 回線 — 受信 — 復元 — 映像出力（承認済みのデザインでは「エンコード」「デコード」。ふつうの言葉に置き換えた）。問題のある段に形と短い説明を付け、切れている区間は破線。余裕が少ないときは「回線　混み合っています」、受信機で映像が止まったときは「映像出力　n 回停止」。
- イベント：新しい順に 4 件。「ログをすべて表示」でログ画面へ。画質の変更は理由つき（「回線に余裕が戻ったため、画質を 2.5 → 3.0 Mbps に上げました」など）。
- 停止：「伝送を停止…」→ 確認 →「伝送を停止する」。停止中は「伝送を開始」（黒いボタン）に変わる。

## 映像設定（送信機）

- 入力：「カメラ」（カメラの名前で選ぶ。デバイスのパスは出さない。検出された入力信号を「実測」として表示。いまは 3840×2160・30p だけ）か「映像ファイル」（機器のフォルダーにある 4K・30p の非圧縮ファイルをファイル名で選ぶ。ファイルの形式と長さ）。運用画面の見出しも同じ名前（「カメラ Facecam 4K　3840×2160　30p」）。
  - 繰り返し再生はまだできないので、チェックボックスを押せない状態で「準備中」を付け、「いまはファイルを最後まで 1 回だけ送ります。」と添える（`VideoOptions.loop_available`）。
- 画質：「画質の決め方」は「おまかせ（おすすめ）」と「画質を固定」。説明は選んでいる方の文を出す。
  - おまかせ：回線が混んだら画質（ビットレート）を下げ、空いたら戻す。1.5〜4.0 Mbps の段階で動く。
  - 画質を固定：1.5〜4.0 Mbps（1 秒あたりに送るデータの量）の値を入力する。初期値は、おまかせがいまめざしている値。回線の推定容量が測れているときは「いまの回線の推定容量は 2.8 Mbps です。これより低めにすると止まりにくくなります。」と添える。
  - 「いまの画質」は「目標 3.5 Mbps／実際 3.3 Mbps」を 1 秒ごとに更新する（`Stats.target_mbps` と `actual_mbps`）。
  - 「映像の形式」は変更できない値として「AV1・入力と同じ解像度とフレームレート（3840×2160・30p）」と出す。括弧の中は、選んでいる入力（カメラかファイル）の値。
- 音声：いまは送らない（設定項目なし）。
- 変更の扱い：変えた行は薄い灰色、ラベルに「変更」、下に「適用中 … 元に戻す」。おまかせから画質を固定に変えると、「固定する画質」も必ず変更に入り、元の値に「（おまかせ）」を付ける。右の「変更内容」に一覧、適用したときの影響、「すべて取り消す」「内容を確認して適用…」。
- 範囲外の入力（1.5〜4.0 Mbps）は行を赤くし、適用ボタンを押せなくする。
- 適用：確認ダイアログ（項目・適用中・変更後、影響）→「適用する」→「適用しています。新しい設定に切り替えています…」→ 右に「HH:MM:SS に適用しました」。画質と決め方の変更は映像を途切れさせずに数秒で切り替わる。入力を変えると接続をやり直すので、受信側の映像が約 10 秒途切れる（影響は 1 行にまとめる）。
- 影響は回線の様子でも変わる（推定容量、おまかせの目標）ので、確認ダイアログを開いたときにも機器に問い合わせ直す。

## 伝送設定（送信機）

- 上の帯：接続エラーのときは大きい帯（次の試行までの秒数、前回の接続、理由の文、「今すぐ再試行」「伝送を停止…」）。停止中は灰色の帯と「伝送を開始」。
- 送信機と受信機の設定を比べる：接続方法（「送信機から接続 → 接続を待つ　● 組み合わせできます」）、接続先とポート、遅延、暗号化（選択肢が複数になったら「暗号化方式」）、パスフレーズ（暗号化が「なし」の間は出さない）。受信機の値は接続したときに受け取ったもの。パスフレーズの値は受信機から送られないので、受信機の拒否理由から「不一致」を出す。遅延は両方が同じでないと「不一致」。
- 選択肢が 1 つしかない項目は操作部品を出さず、文字で示す（`TransportOptions`）。いまは「接続方法　この送信機から受信機へ接続します」と「暗号化　なし」。
- 接続：接続方法（選択肢が複数あるときは「送信機から接続」「接続を待つ」「互いに接続」。説明には選んでいる方の文を出す）。送信機から接続と互いに接続では接続先（IP とポート）、接続を待つと互いに接続では待ち受けポート。
- 遅延：「標準（約 10 秒）— 回線が乱れても映像が止まりにくい」と「低遅延（約 1.5 秒）— おまかせは使えず、画質は固定になります。回線が乱れると映像が止まりやすい」を説明つきの選択肢で出す。説明は「送信機に入った映像が受信側に映るまでの時間です」（ファイルの入力もあるので「撮影」とは書かない）。低遅延は最初の版では使えないので、押せない状態で「準備中」を付ける（`available: false`）。
- 暗号化：暗号化方式、パスフレーズ（書き込み専用。入力したときだけ変更になる。「表示する」で見える）。受信機に拒否された時刻を表示する。文字数の範囲は範囲外のときだけ出す。暗号化が「なし」の間はパスフレーズの欄を出さない。
- 適用すると接続をやり直す（受信側の映像が約 10 秒途切れる）。未接続なら受信側への追加の影響はない。

## 全画面表示

| 項目 | 決めたこと |
| --- | --- |
| 開く | 「全画面」ボタン、F キー（入力中は除く） |
| 閉じる | 「全画面を終了」、Esc、もう一度 F。閉じたら「全画面」ボタンにフォーカスを戻す |
| 上の帯 | 機器名、映像の種類、形式、状態、時刻、セーフエリア（93%・90%）の切り替え、「全画面を終了」 |
| 帯を隠す | 3 秒操作がないと帯とカーソルを隠す。マウス、タップ、キーで戻る |
| 警告・エラー | 帯とは別に上に出し続ける。正常に戻ったら「回復しました」を 10 秒出す |
| 置かないもの | 停止や設定の変更 |
| 映像がないとき | 中央に「受信映像なし」と理由。映像はあるが伝送中でないときは「プレビューは伝送中だけ表示します。」 |
| 映像 | 運用画面と同じプレビュー（準備中・表示できないときの表示も同じ）。運用画面との行き来では、いったん閉じて開き直す |
| 全画面にできないとき | ページの中で最大化して同じ表示にする |
| 機器の負荷 | タブが裏に回ったらプレビューを閉じる |

## 未デザインの画面（仮の画面あり）

- 受信機の映像設定（出力先・出力形式）と伝送設定（待ち受けポート・パスフレーズ）
- 録画
- ネットワーク（回線テストの動作確認用に、仮のボタンと結果だけ置いている）
- ログ（イベントの一覧だけ。絞り込み・書き出しは未定）
- 機器情報（項目とライセンス表示の場所は仮）
- ログイン（LAN 内の画面の認証。方式は未定）

## 決まっていないこと

1. **映像ファイルの追加方法**：ブラウザからのアップロードが要るか（いまは機器の `/srv/media` にあるファイルを選ぶだけ）。繰り返し再生は準備中。
2. **音声**：送るようにするときの設定項目と、運用画面のメーター。
3. **ログイン**：パスワードの持ち方、セッションの長さ、HTTPS にするか。
4. **低遅延を選んだときの画質**：低遅延では画質を固定にする（おまかせは使わない）ことにしている。選んだときにいまの値で固定へ切り替えるか、先に「画質を固定」を選んでもらうかは、低遅延を使えるようにするときに決める。
