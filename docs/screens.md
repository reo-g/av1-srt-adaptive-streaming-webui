# 画面の仕様

デザインは `design/screens/*.png`（元は Claude の Design キャンバス「改訂案」ページ）。実装は `web/src/pages/` にあり、モックで動きます。ここには、画像だけでは分からない動きと、決めたこと・決まっていないことを書きます。

## 共通

- **左のメニュー**：運用／設定（映像・伝送・録画）／管理（ネットワーク・ログ・機器情報）。未適用の変更がある設定画面には件数のバッジを出す。
- **ヘッダー**：機器名・役割・IP アドレス、状態（形と文字）、機器の時刻（`10:42:18 JST`）。時刻は機器の時計で、ブラウザの時計ではない。
- **警告の帯**：ヘッダーの下。▲ 警告（黄）、■ 接続エラー（赤）。自動では消えない。運用画面では「伝送設定を開く」を添える。
- **状態の形**：● 正常 ▲ 警告 ■ エラー ○ 停止・待ち受け — 未取得。色だけで区別しない。
- **配色**：白基調、強調は黒（`web/src/styles/app.css` の変数）。文字 14px、角丸 4px、数値は等幅数字。
- **確認ダイアログ**：停止と取り消しは赤いボタン。開いたら安全な方のボタンにフォーカス、Esc で閉じ、閉じたら元の場所へフォーカスを戻す。

## 運用（送信機・受信機）

- 左：入力映像（送信機）／受信映像（受信機）のプレビュー、形式、「全画面」、音声（いまは「なし」）、信号経路。
- 右：計測値 4 つと直近 5 分の推移（破線は基準）、「回線の詳細」、停止・開始ボタン。
  - 送信機：送信ビットレート、パケット損失、RTT、推定帯域。詳細は再送率、送信が間に合わなかったパケット（5 分）、伝送バッファ（自動／手動）。
  - 受信機：受信ビットレート、パケット損失、映像の欠落、映像遅延（実測）。詳細は RTT、再送の割合、回復できなかったパケット（5 分）。
  - 取れない値は「—」と理由（未接続のため取得できません／未取得（前回 38 ms）／停止中）。
- 信号経路：送信機は 入力 — エンコード — 送出 — 回線 — 受信機、受信機は 送信機 — 回線 — 受信 — デコード — 映像出力。問題のある段に形と短い説明を付け、切れている区間は破線。
- イベント：新しい順に 4 件。「ログをすべて表示」でログ画面へ。
- 停止：「伝送を停止…」→ 確認 →「伝送を停止する」。停止中は「伝送を開始」（黒いボタン）に変わる。

## 映像設定（送信機）

- 入力：「カメラ」（`/dev/video*` を選ぶ。検出された入力信号を「実測」として表示）か「映像ファイル」（ファイルを選ぶ。繰り返し再生、ファイルの形式と長さ）。
- 映像エンコード：既定は「自動」。自動のときは機器が決めた値（解像度・フレームレート・ビットレート・コーデック）を読み取り専用で表示。
- 「手動」にすると、自動のときの値を初期値として、解像度・フレームレート・ビットレート・レート制御を編集できる。コーデック・プロファイル・キーフレーム間隔・B フレーム・エンコーダは「詳細設定（5 項目）」の中。
  - 詳細設定は閉じた状態で始める（デザインのボードは中身を見せるため開いていた）。閉じていて中に変更があるときは「変更 n 件を含む」を出す。
- 音声：いまは送らない（設定項目なし）。
- 変更の扱い：変えた行は薄い灰色、ラベルに「変更」、下に「適用中 … 元に戻す」。自動から手動への変更では、元の値に「（自動）」を付ける。右の「変更内容」に一覧、適用したときの影響、「すべて取り消す」「内容を確認して適用…」。
- 範囲外の入力（ビットレート 1〜40、キーフレーム間隔 0.5〜10）は行を赤くし、適用ボタンを押せなくする。
- 適用：確認ダイアログ（項目・適用中・変更後、影響）→「適用する」→「適用しています。エンコーダを再初期化中です…」→ 右に「HH:MM:SS に適用しました」。

## 伝送設定（送信機）

- 上の帯：接続エラーのときは大きい帯（次の試行までの秒数、前回の接続、理由の文、「今すぐ再試行」「伝送を停止…」）。停止中は灰色の帯と「伝送を開始」。
- 送信機と受信機の設定を比べる：接続モード、接続先とポート、伝送バッファ、暗号化方式、パスフレーズ。受信機の値は接続したときに受け取ったもの。パスフレーズの値は受信機から送られないので、受信機の拒否理由から「不一致」を出す。伝送バッファは大きい方で動く。
- 接続：接続モード（発信／待ち受け／相互接続）。発信と相互接続では接続先（IP とポート）、待ち受けと相互接続では待ち受けポート。
- 遅延：伝送バッファ。既定は「自動」（前回の RTT から機器が決めた値を表示）。「手動」にすると 80〜1000 ms から選ぶ。初期値は自動のときの値。目安（RTT の 4 倍以上）より短いと警告。
- 暗号化：暗号化方式、パスフレーズ（書き込み専用。入力したときだけ変更になる。「表示する」で見える）。受信機に拒否された時刻を表示する。文字数の範囲は範囲外のときだけ出す。
- 適用すると接続をやり直す。未接続なら受信側への追加の影響はない。

## 全画面表示

| 項目 | 決めたこと |
| --- | --- |
| 開く | 「全画面」ボタン、F キー（入力中は除く） |
| 閉じる | 「全画面を終了」、Esc、もう一度 F。閉じたら「全画面」ボタンにフォーカスを戻す |
| 上の帯 | 機器名、映像の種類、形式、状態、時刻、セーフエリア（93%・90%）の切り替え、「全画面を終了」 |
| 帯を隠す | 3 秒操作がないと帯とカーソルを隠す。マウス、タップ、キーで戻る |
| 警告・エラー | 帯とは別に上に出し続ける。正常に戻ったら「回復しました」を 10 秒出す |
| 置かないもの | 停止や設定の変更 |
| 映像がないとき | 中央に「受信映像なし」と理由 |
| 全画面にできないとき | ページの中で最大化して同じ表示にする |
| 機器の負荷 | タブが裏に回ったらプレビューの取得を止める |

## 未デザインの画面（仮の画面あり）

- 受信機の映像設定（出力先・出力形式）と伝送設定（待ち受けポート・パスフレーズ）
- 録画
- ネットワーク（回線テストの動作確認用に、仮のボタンと結果だけ置いている）
- ログ（イベントの一覧だけ。絞り込み・書き出しは未定）
- 機器情報（項目とライセンス表示の場所は仮）
- ログイン（LAN 内の画面の認証。方式は未定）

## 決まっていないこと

1. **全画面での画質**：いまのプレビューは約 5 fps の縮小映像。全画面のときだけ品質を上げる（例：720p・30 fps、WebRTC）か、5 fps のまま「約 5 fps」と示すか。機器の負荷と LAN の帯域を見て決める。
2. **映像ファイルの追加方法**：ブラウザからのアップロードが要るか（いまは機器の `/srv/media` にあるファイルを選ぶだけ）。
3. **音声**：送るようにするときの設定項目と、運用画面のメーター。
4. **ログイン**：パスワードの持ち方、セッションの長さ、HTTPS にするか。
